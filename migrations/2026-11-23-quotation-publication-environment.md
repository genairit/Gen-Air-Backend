# Durable quotation PDF publication

Date: 2026-11-23

Apply `2026-11-23-quotation-publication-ledger.sql` before deploying the Backend publisher. This additive migration binds the actual unambiguous root template rows named הצעות מחיר and הזמנה לביצוע, and adds ארכיון הצעות מחיר at the same root level. Existing role bindings survive renames. Ambiguous or missing configured roles stop migration for repair. It neither renames client folders nor sweeps historical files. New tables are private, RLS enabled, with Data API grants revoked.

Deploy the compatible Worker contract before Backend. PDF jobs use `${WORKER_QUEUE_PREFIX}.pdf.jobs` and PDF results `${WORKER_QUEUE_PREFIX}.pdf.results`, isolated from unchanged CSV queues during rolling deployment. Worker alone renders; it receives no Google credentials. Backend adopts accepted bytes transactionally before acknowledging results. Lost broker confirmations may redeliver the same job; the first validated accepted SHA256 remains authoritative even after its retry bytes are released.

Backend variables:

- `RABBITMQ_URL`: required for automatic publication; same environment's existing Worker Rabbit connection, for example `amqp://local_user:local_password@localhost:5672`. Use the platform's Worker service variable reference; do not copy credentials to source.
- `WORKER_QUEUE_PREFIX`: optional, defaults to `genair.worker.v1`; must exactly match the paired Worker. Shape: 1–100 ASCII letters, digits, dots, underscores or hyphens.
- `RAILWAY_DEPLOYMENT_DRAINING_SECONDS`: set to `180` on Backend and Worker, allowing bounded active operations to drain on SIGTERM. This is a deployment platform variable, not a client setting. Stop new work and new Drive effect steps, await the current bounded request and active result adoption, then close broker and DB. Each publication Drive request has a 40-second transport bound with automatic retries disabled; the drain guard also applies between revision-pin update and read-back, and between listing pages. A hard crash still requires reconciliation.

Existing `WORKER_URL` / `WORKER_API_TOKEN` continue serving authorized synchronous manual downloads; manual download never uploads or queues. Existing Google service account/root configuration stays on Backend. Broker unavailability leaves the committed business status and durable outbox pending; the periodic dispatcher reconnects. Rendering exhaustion/timeouts become a safe visible failure and explicit retry. Retry uses the failed cycle/generation and the original business action's mutation permission; it accepts no destination, project, file or job input.

The maximum job envelope is 1MiB; the maximum PDF is 4MiB; PDF results are at most 6MiB including base64. Each cycle has at most one proposal and one order artifact. Full server renderer payload, complete source document including rules, print date, naming inputs, final filename and `quotation-filename.v1` policy are captured once and canonically hashed. Later customer/project/issuer edits do not change those inputs. Task187 can supply a new filename policy for new snapshots; existing operations always use their frozen final filename.

Accepted retry bytes are released only after the exact Drive binary revision is pinned and read back with `keepForever=true` and matching MD5. SHA256, MD5 and revision identity remain immutable. If this Drive capability is unsupported or denied, the same bounded bytes remain in the private ledger for the lifetime of that cycle as the explicit preservation fallback, at most 8MiB per cycle. No new storage service is introduced. Never label a current Drive URL as a historical proposal byte download: history links identify the cycle's current/final file only. Archive verifies the final accepted stage checksum and moves that same identity; future review creates a distinct cycle/file.

Financial transactions contain no broker or Drive request. Lifecycle changes and the executor use the same PostgreSQL transaction advisory lock before quotation row access. Effect intent and reserved IDs commit before the executor starts a separate, locked effect transaction; its checks and adoption use that transaction's connection, including under transaction pooling. Project role folder reservation additionally serializes on the project. No expiring lease permits a successor to overwrite uncertain in-flight media. External transport failures remain visible and reuse the exact reserved identity and accepted hash. A process crash can cause temporary external divergence because Google and PostgreSQL cannot commit atomically; reconciliation checks tagged identity, MIME, known project parent and checksum before progressing. Missing/hidden previously accepted identities are never recreated automatically.

Managed project roots may add only the required role folder. Linked roots require explicit existing `complete_template` provisioning; background publication never fills a linked template. Apartments use their exact own root after ancestry validation. Withdrawal uses the tracked cycle's original canonical project even when the incoming editor save changes projects. Customer-only quotations retain their business flow and manual downloads with publication not applicable. Drafts, clones and autosave create no publication work; no old-file backfill is performed.

Rollback: stop/drain Backend dispatch before reverting application code; retain all ledger rows, bytes, reserved identities and template bindings. Do not drop private evidence or re-enable the old manual-export upload side effect. Keep the compatible Worker until PDF queues are reconciled/drained. Apply and verify the same SQL and paired environment references separately in test and production during the authorized release; development application does not imply those environments have migrated.
