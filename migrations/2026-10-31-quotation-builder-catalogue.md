# Quotation builder rollout

Apply schema SQL before backend, then frontend. No shared migration or catalogue activation was performed during development. Apply the separate seed only after catalogue owner review. It contains1,637source rows; all10records across5duplicate SKU groups start as conflict,8nosell rows remain unselectable, zero-price rows remain valid. Resolve via catalogue maintenance by explicitly archiving losers and activating one winner. No first-wins selection. Stable IDs make seed retry safe without overwriting edits/snapshots.

The backend uses its existing private database role. New tables enable RLS with no public Data API policies/grants. Do not grant anon/authenticated access; all access goes through existing action permissions. Initial write/approve/catalogue grants: system_admin (management); read follows existing projects.read roles. Update DB role_permissions through the normal controlled process, no permission editor UI.

Numbering YYMM-000001 is allocated under a monthly transaction lock. Aggregate row locks and required version prevent lost updates. Initial payment terms copied once from customer; later customer changes and quotation customer relinking preserve quotation-local overrides. Customer defaults may be null. Quotation note starts empty. Existing project payment fields are untouched: their removal remains task100.

Review transitions draft→review→approved; review→draft and approved→draft reuse the same ID. Only approval permission may acknowledge required warnings or transition. Self-approval allowed. Any content save resets status to draft, clears acknowledgements and approval metadata. No revision/sent-document storage, email/PDF/Drive/Priority integration.

Amounts are decimal strings, quantities/prices4decimal places; round each billable line extension to2places half-up, sum those rounded lines, then round discounted pretax and VAT to2places half-up. Target pretax overrides percentage, including zero; stored VAT default18%. New persisted line or replacement catalogue selection counts once for acting user; autosave/render never increments unchanged selections. Included remote/thermostat metadata copied from source. All applicable prototype advisory/check rules are converted to REQUIRED warnings, as clarified2026-10-31: zero price, less-useful, capacity distance, payment-schedule totals and outdoor-without-indoor also block approval until resolved or explicitly acknowledged. There is no separate advisory category. Capacity matching remains a search concern.

Rollback: roll back frontend/backend first, retain additive tables/customer default to avoid data loss. No destructive automatic down migration. Test/prod require their own reviewed rollout, not implied by feature implementation.

Rules configuration is stored in quotation_rules; supported keys and parameter shapes are validated by backend code. Enable/disable and thresholds change through new reviewed migrations; increment rule version. No rules UI or executable expressions. Draft/review reads re-evaluate current settings and clear effective acknowledgements on fingerprint changes. Approved quotation stores the approved configuration snapshot. Acknowledgement keys include configuration fingerprint.
