# Durable recommended quotation clones

Apply the adjacent SQL migration before deploying the backend endpoint, then deploy the frontend. The legacy manual `POST /quotation/:id/clone` is unchanged for rolling deployments. No environment variables, secrets, data rewrites or shared-environment changes were made by this implementation.

`POST /quotation/:id/clone-recommended` accepts `sourceVersion`, `targetBrand`, and UUID `idempotencyKey` and returns the full draft detail with 201, including replay. Actor plus command UUID uniquely identifies a command. Its SHA-256 payload includes canonical lowercase source UUID, source version and exact target brand. Command serialization precedes source locking. Successful command lookup precedes version validation; replay still requires current feature permissions and a readable result quotation. Source/customer/project retirement does not rerun creation availability checks or block reopening an existing result. Changed payload returns 409. Draft, number, items, project/apartment/task associations and command commit together. Response metadata is read after commit.

Commands have no expiry. Do not purge successful commands: doing so removes retry protection. Actor and result foreign keys restrict hard deletion; ordinary soft deletion retains the command. The table is backend private: RLS enabled, no client policies, all client/PUBLIC privileges revoked. The backend's existing privileged database connection performs access after application authorization. No SQL functions are introduced.

Selection uses the shared catalogue query with exact active target brand before limit 1, compatible system (including catalogue null system), source role and equipment type, and positive capacity when the source has positive capacity. Ordering is capacity delta, actor selection count descending, used preference descending, SKU then immutable ID. Zero/null source capacity does not constrain capacity. Each line chooses its first candidate; the complete draft must pass existing parent/accessory validation. An incompatible first-ranked combination fails with source SKU/reason rather than silently trying an undocumented combination. Missing source catalogue data fails; General snapshots/placement/quantities remain intact. General-only and multi-brand sources remain unsupported. Source is never changed and clone adds secondary task links, including clone of a secondary.

Rollback application code first, retaining the additive table and legacy endpoint. Dropping the table is a deliberate loss of retry protection and requires an explicit retention decision; it is not part of deployment rollback.
